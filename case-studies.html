1. Creating Experian's First Design System

Artifact Ideas

  • Animation
  • Tokens
  • Swatches
  • Components
  • Typography

Problem

No formal design system. Multiple domain teams independently creating UI patterns. Style guide offered guidance but no enforceable standards. Led to inconsistency, ongoing debate, slow decision-making.

Scope of Ownership

Directly Owned

  • Buy-in communication with Design & Engineering Managers
  • First reusable libraries (iOS, Android, Web)
  • First Slack support channels + intake workflows
  • First base/alias token system
  • Typography scale
  • Design QA process (reviewing projects for system alignment)

Influenced

  • Designers creating domain-specific reusable components
  • Shift toward global/systems thinking

Tradeoffs & Hard Calls

  • Pushed back on skeptical engineering who didn't believe DS was needed
  • Sold value: centralized decisions, reusable code, faster shipping, baked-in accessibility
  • DSQA effort failed — couldn't scale without more resources; pushed ownership back to domain leads
  • Educated designers that overriding/detaching instances created confusion for developers

Impact

  • DS formalized into first official team (Keith + 2 native designers)
  • Brett became team lead; enabled clearer communication to leadership
  • Adam (head of design) mandated all new projects use the DS
  • Engineering impact: less custom code, fewer bugs
  • High engagement in Slack support channels

2. Atlas Component Merge Across Platforms

Artifact Ideas

  • Animation
  • Unmerged and merged components
  • Wireframe animation showing merge + breaking changes

Problem

Platform-specific libraries evolved independently (web, iOS, Android). Web had separate mobile/tablet/desktop breakpoints. Fragmentation led to duplicated patterns, inconsistent behavior, maintenance overhead.

Scope of Ownership

Co-owned with Caleb

  • Divided component list
  • Created branches, merged, released in waves over 2 months
  • Created formal 4-step deprecation process
  • Slack announcements + Loom videos
  • 1:1 meetings with designers for check-ins and demos

Tradeoffs & Hard Calls

  • Hard sell — created update work and design debt for designers
  • Knew long-term time savings outweighed short-term pain
  • Got buy-in from Brett, then Adam
  • Gave Adam a process + timeline for tracking

Impact

  • Fewer Figma frames — same component works across iOS, Android, Web
  • Centralized design decisions
  • Reduced platform-switching overhead
  • Designers' Figma skills greatly increased
  • Keith and Caleb became the Figma experts

3. Atlas Audit — Design System Adoption Tool

Artifact Ideas

  • Animation
  • Atlas Audit UI
  • Highlights
  • Information panel
  • Legend

Problem

Multiple UI systems coexisted (Legacy, Next, Atlas, SDUI). No visibility into what was running in production. Adoption was abstract, slow, hard to operationalize.

Scope of Ownership

Directly Owned

  • Owned idea completely
  • Created Figma prototype for developers
  • Collaborated with engineers for feedback
  • Did this autonomously — Brett/Adam trusted Keith to pursue ideas

Influenced

  • Inspired other team members to create their own internal tools
  • Shifted developers' mindset — they started bringing ideas forward
  • Showed you identify and solve problems, not just work Jira tickets

Tradeoffs & Hard Calls

  • Increased personal workload, but believed in it
  • Used as team bonding — fun project outside day-to-day work
  • Target user (Product Managers) far removed from DS team — harder adoption
  • Requires patience — internal tools are lower priority

Impact

  • Surfaced work for offshore engineering team running low on tasks
  • Prevented wasted contract time/money
  • Made tech debt visible and actionable
  • Turned abstract "adoption" into concrete, prioritized work items
